# LINE配信のつくりかた（運用者ガイド）

このガイドは、パソコンの専門知識がなくても、Notion の画面だけで LINE のお知らせを送るためのものです。

> **このファイルと Notion 版の関係**: 運用者が読むのは Notion 版
> （<https://app.notion.com/p/39970c9d064c81dabf04f65c073d667c>）です。本ファイルはリポジトリ側の写しで、
> **配信まわりのコードを変えたときは、このファイルと Notion 版を必ず同時に直します**。
> コマンドの正本（本番／検証環境の切り替え・スイッチ操作）は `docs/deploy-runbook.md` の
> 「LINE 配信の運用ゲート」節です。

---

## いまの状態（最初に必ず読む）

| 項目 | いまの状態 | 意味 |
|---|---|---|
| 本番の実送信スイッチ | **OFF** | Notion で「承認」してもお客さまには**届きません**（練習と同じ状態） |
| 承認のしかた | **単独運用モード** | Setaka ひとりで承認できます（別の承認者は不要） |
| 検証環境での実配信 | **実証済み**（2026-07-27） | テスト用 LINE へ写真つきで 4/4 件届くことを確認済み |

- **本番の実送信スイッチが OFF のあいだは、Notion 上で「承認」まで進めても、実際の送信は起きません。**
  仕組みは中身の確認だけをして止まります（Notion の Status も「Approved」のまま変わりません）。
  「送ったつもり」にならないよう、実際に届くのは**スイッチを ON にしたあと**だと覚えておいてください。
- スイッチを ON にする作業は Setaka が行います（手順は下の「実運用を開始するとき」）。

## これは何？

Notion の「配信コンテンツ」の表に **新しい行を1つ作って、文章と写真を入れて、送り先と日時を選んで「承認」する**だけで、LINE のお知らせが自動で送られる仕組みです。むずかしい操作や、URL・プログラムの知識はいりません。

作業する場所は、Notion の「配信コンテンツ」を開いて、上のタブから **「かんたん配信（運用者用）」** を選んでください。ここには、あなたが使う欄だけが表示されています。

## つくりかた（5ステップ）

### ① 新しい行を作る
表のいちばん下の「＋ 新規」を押して、空っぽの行を1つ作ります。
（「【サンプル】使い方の見本」の行は消さずにそのまま置いておいてください。書き方のお手本です。）

### ② タイトルと本文を書く
- **配信タイトル**：あとで自分が見分けるための名前です（例：「夏の新作のお知らせ」）。お客さまには届きません。
- **本文**：LINE で送りたい文章そのものです。ここに書いた内容がそのまま届きます。

> **⚠ 飾り記号は使わないでください。** LINE は書いた文字を**そのまま**表示します。太字にするつもりで
> `**新作のお知らせ**` と書くと、お客さまの画面には `**新作のお知らせ**` と**アスタリスクごと**表示されます。
> 見出し記号（`#`）・箇条書き記号（`-` `*`）・リンク記法（`[表示文字](URL)`）も同じで、そのまま出ます。
> 強調したいときは改行と空行で区切る、URL はそのまま貼る（`https://...` と直接書く）でお願いします。

### ③ 写真を入れる（写真がないときは飛ばしてOK）
**「画像」の欄に、送りたい写真をそのままドラッグ＆ドロップ**してください。パソコンの中の写真ファイルを、マウスでつまんで欄の上で放すだけです。
- 複数枚入れると、**並べた順番のまま**お客さまに届きます。
- 写真を入れれば「写真つきのお知らせ」、入れなければ「文章だけのお知らせ」に自動でなります。切り替えの操作はいりません。
- 写真は **JPEG か PNG**、大きさは **10MB まで**にしてください。iPhone の HEIC 形式や、大きすぎる写真は **そのままでは承認されません**（お客さまに壊れた写真が届かないよう、仕組みが自動で止めます）。この場合は「Status」が「Approved」から自動で戻り、**「エラー詳細」の欄に「画像○が…」というメッセージ**が出ます。写真を JPEG か PNG に保存し直してから、もう一度承認してください。

### ④ 送り先と日時を選ぶ
- **配信対象**：だれに送るかを選びます。
  - **全員** … LINE の友だち全員
  - **癒し** / **探求** / **味覚** … 好みのタイプ別に送る
  - **社内** … 社内のテスト用（本番のお客さまには届きません）
- **配信予定日時**：送りたい日と**時刻**を選びます。**日付だけでなく時刻まで**必ず入れてください（時刻が空だと送られません）。

> **⚠ 過去の日時を入れない。** 配信予定日時が**すでに過ぎている**行を承認すると、次の自動チェック
> （最大15分後）で**すぐに送信対象**になります。「あとで直そう」と思って過去日時のまま承認しないでください。

### ⑤ 承認する
内容を最後に確認したら、**「Status」を「Approved（承認）」に変えます**。この操作だけで完了です。**あなたがボタンを押したり、URL やプログラムを操作したりする必要はいっさいありません。**

承認したあとは、**仕組みが15分に1回、承認された配信がないかを自動で見に行きます**。あなたの行が見つかると、内容をその時点で確定（写真も保存）し、**選んだ日時になったら自動で送られます**。ですので、承認してから送信までは最大で15分ほどの余裕を見ておいてください（配信予定日時ちょうどに送りたいときは、その少し前までに承認しておくと安心です）。

> **承認者の入れかたが変わりました（2026-07-25〜・単独運用モード）**
>
> - 以前は「書いた人とは**別の人**」を承認者に入れる必要がありましたが、いまは **書いた人と同じ人（Setaka）で承認できます**。
> - ただし **「承認者」の欄を空にはできません**。空のままだと仕組みが「承認されていない」と判断して**送りません**。
>   自分ひとりで進める場合も、**「承認者」に自分を入れてから** Status を Approved にしてください。
> - この扱いは、Setaka の承認にもとづく設定で有効になっています（決定記録:
>   <https://app.notion.com/p/3a870c9d064c81f986ddc7a8b805d6af>）。設定を外せば「別の承認者が必須」に戻ります。

もし写真に問題（HEIC 形式・10MB 超など）があると、承認は自動で取り消され、「エラー詳細」の欄にわかりやすいメッセージが出ます。その場合は写真を直して、もう一度承認してください。

## やってはいけないこと

- **承認したあとに、本文や写真を書き換えない**でください。書き換えると承認が自動で取り消され、送られません（もう一度承認し直せば大丈夫です）。
- **「Status」を勝手に「Sending」や「Sent」にしない**でください。ここは仕組みが自動でつけます。
- **タイトル・本文・画像・配信対象・配信予定日時・Status 以外の欄はさわらない**でください。他の欄は仕組みが使う欄です（見えていない欄も含めて、そのままにしておいてください）。
- **飾り記号（`**` `#` `-` など）を本文に書かない**でください（そのまま表示されます）。
- **過去の日時のまま承認しない**でください（すぐ送信対象になります）。

## 送るのをやめたい・止めたいとき

| したいこと | やりかた | 効き目 |
|---|---|---|
| この1件を送らない | 「Status」を **Approved → Draft** に戻す | 予定時刻より前なら止まります。承認は外れ、送信対象から外れます |
| これから送る配信を**すべて**止める | Setaka が実送信スイッチを OFF にする（下の「実運用を開始するとき」参照） | 以降の配信は全部止まります（承認済みの行も送られません） |
| 承認のしかたを元（別の承認者が必須）に戻す | Setaka が単独運用モードの設定を外す | 以降、自分ひとりでの承認が通らなくなります |

- **予定時刻まで15分を切っている／すでに過ぎているときは、間に合わない可能性があります。** すぐ Setaka に連絡してください。
- **送信済みのものは取り消せません。** 訂正するときは、お詫び・訂正の配信を新しく作って承認します。

## 実運用を開始するとき（Setaka の作業・お客さまに届くようにする）

実送信スイッチを ON にすると、**その次の自動チェック（最大15分後）から、条件のそろった承認済みの行が実際にお客さまへ送られます**。

### ⚠ ON にする前に必ず「Approved の行を全部見る」（省略禁止）

**なぜ必要か**: スイッチが OFF のあいだ、承認した行は Notion 上に**「Approved のまま」たまり続けます**
（OFF のときは仕組みが Notion を書き換えないため、Status も日時も承認当時のまま残ります）。
その状態でスイッチを ON にすると、**配信予定日時がすでに過ぎている行がまとめて「送信待ち」と判定され、
次の自動チェックで一斉に送信されます**。テストのつもりで承認した古い行が、本番のお客さまに突然届く事故になります。

**手順**（ON の直前に毎回行う）:

1. 本番の「配信コンテンツ」を開き、**Status = Approved の行を絞り込んで全部並べる**（1件も飛ばさない）。
2. 1行ずつ、次を確認する。
   - **配信予定日時が過去になっていないか**（過去なら ON 直後に飛ぶ）。
   - **いま本当に送ってよい内容か**（試し書き・下書き・古いお知らせが混ざっていないか）。
   - **送信済みチェックが付いていないか**（付いていれば再送はされません）。
3. 送るつもりのない行は **Status を Draft に戻す**（消さずに下書きへ）。
   いま送ってよい行だけを Approved のまま残す。
4. **Approved の行が「意図した行だけ」になったことを確認してから**、スイッチを ON にする。

### スイッチの操作（Setaka が実行）

```bash
# ON にする（本番の実送信を有効化）
bash scripts/go-live-enable-send.sh --confirm-i-really-want-to-send-real-line

# OFF に戻す（すぐ止める・練習状態へ復帰）
pnpm exec wrangler secret delete DELIVERY_SEND_ENABLED
```

ON にしたあとは、**最初の1本が届いたことを実機で確認**してから、続きの配信を承認してください。

## テストしたいとき（お客さまに届かない環境で練習する）

練習・確認は**必ず検証環境（テスト用 LINE @426vlcyb）** で行います。本番の「配信コンテンツ」で練習しないでください。

1. **テスト用の表に行を作る**: 「[TEST] 配信コンテンツ (staging/@426vlcyb)」
   （<https://app.notion.com/p/3a970c9d064c816aaf11cf790334957a>）に、本番と同じ手順で行を作って承認します。
   **本番の「配信コンテンツ」には作りません。**
2. **検証環境の送信スイッチを一時的に ON にする**（Setaka が実行）。
3. **届くのを待って、テスト用 LINE の実機で確認する**（写真の順番・文字化け・改行を目視）。
4. **終わったら必ず OFF に戻す**。戻し忘れると、テスト用の行が承認されるたびに送信され続けます。

コマンドは `docs/deploy-runbook.md` の「LINE 配信の運用ゲート」を参照してください。
**`--env staging` を必ず付けます。付け忘れると本番（お客さま）に対する操作になります。**

## 困ったとき

- **送られない**：①「Status」が「Approved」になっているか ②「承認者」の欄に人が入っているか ③「配信対象」が選ばれているか ④「配信予定日時」に**時刻まで**入っているか、を確認してください。どれか空だと送られません。承認してすぐには送られません（仕組みが15分に1回見に行くため、少し待ってください）。また、**本番の実送信スイッチが OFF のあいだは、条件がそろっていても届きません**（いまの状態は冒頭の表を確認）。
- **「エラー詳細」の欄に赤いメッセージ（文章）が出ている**：まずそのメッセージを読んでください。多くは写真の問題です（例：「画像2がLINEで表示できない形式です（HEIC）。JPEG か PNG にしてください。」）。書かれているとおりに直して、もう一度「Status」を「Approved」にしてください。直れば承認が通り、メッセージは消えます。
- **写真が表示されない／承認が通らない**：写真が JPEG か PNG か、10MB 以下かを確認してください。iPhone の写真（HEIC）は JPEG に保存し直すと直ります。
- **承認が勝手に外れた**：承認のあとに内容を変えたか、写真に問題があった可能性があります。「エラー詳細」の欄を確認し、直してから承認し直してください。
- **本文に `**` や `#` がそのまま出た**：飾り記号は使えません。記号を消して、改行と空行で読みやすくしてください。
- それでも分からないときは、担当エンジニアに「配信コンテンツの◯◯（タイトル名）が送れない」と伝えてください。

## いま残っているリスク（知ったうえで運用する）

- **人の目で止める場所が1か所しかありません。** 単独運用モードでは「別の人が確認する」段階がなくなり、
  配信ごとの人間チェックは**「Notion に書いて Approved にする」その一手**だけになります。
  打ち間違い・宛先の選び間違いをその場で拾う仕組みは（形式チェックを除いて）ありません。
- したがって、**Notion の「配信コンテンツ」を編集できる人の範囲が、そのまま「お客さまに送れる人の範囲」**になります。
  権限を持つ人を増やすときは、配信を送れる人を増やすことと同じだと考えて判断してください。
- **戻せます**: 単独運用モードの設定を外せば、その時点から「別の承認者が必須」に戻ります（下の「関連」参照）。
